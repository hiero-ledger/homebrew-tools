# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

A [Homebrew tap](https://docs.brew.sh/Taps) for the `hiero-ledger` project. It hosts Ruby formula files that let users install tools like `solo` via `brew install hiero-ledger/tools/solo`.

## Formula Structure

- `Formula/solo.rb` — the **current/latest** formula, always generated from the template (never hand-edited for version fields)
- `Formula/solo.template.rb` — source of truth for formula logic; contains `__SOLO_VERSION__` and `__SOLO_SHA256__` placeholders
- `Formula/solo@<x.y.z>.rb` — pinned versioned formulas, generated by the update script; class is named `SoloAT<version-nodots>` (e.g., `SoloAT0790`)
- `Formula/hiero-cli.rb` — a simpler formula for the Hedera CLI; not versioned the same way

## Bumping the Solo Version

Run the update script directly (requires `curl` and `sha256sum`/`shasum`):

```bash
.github/scripts/update-solo-formula.sh <new-version>
# or
NEW_VERSION=0.81.0 .github/scripts/update-solo-formula.sh
```

This script:
1. Reads the current version from `Formula/solo.rb`
2. Copies `solo.rb` → `Formula/solo@<current-version>.rb` (pinned formula) and renames the class
3. Copies `solo.template.rb` → `solo.rb` and substitutes `__SOLO_VERSION__` and `__SOLO_SHA256__`

The GitHub Actions workflow (`update-solo-formula.yml`) runs this script and opens a PR automatically; it is triggered via `workflow_dispatch` with a version input.

## Local Formula Validation

```bash
# Audit formula syntax and style
brew audit --formula Formula/solo.rb

# Install from local source (skips cache pull)
HOMEBREW_NO_SOLO_CACHE=1 brew install --build-from-source Formula/solo.rb

# Run the formula's test block
brew test hiero-ledger/tools/solo
```

To tap the local repo for testing against CI scenarios:
```bash
brew tap --custom-remote hiero-ledger/tools "$PWD"
brew trust --tap hiero-ledger/tools
```

## CI Workflows

- **`test-brew-install.yml`** — runs on PRs touching `Formula/`. Tests 8 conflict scenarios (npm, nvm, brew, npm-link, stale symlinks, permission errors) on macOS and Ubuntu.
- **`test-brew-install-version.yml`** — runs on merge to `main` when `Formula/solo.rb` changes. Verifies the installed version matches the formula version and runs a one-shot deploy/destroy smoke test on Linux.
- **`test-brew-install-retry.yml`** — additional retry-focused scenario testing.

`HOMEBREW_NO_SOLO_CACHE=1` is always set in CI to skip the `solo cache image pull` step (which would time out without a running Docker daemon).

## solo.rb Install Logic

The `install` method handles a complex pre-install cleanup sequence before running `npm install`:

1. **Step 1** — Remove any stale or non-Homebrew `$HOMEBREW_PREFIX/bin/solo` symlink/file
2. **Step 2** — Remove all other `solo` binaries found in PATH (npm global, custom prefixes); nvm-managed installs emit a warning but are not removed automatically
3. **Step 2b** — Scan `~/.nvm` for solo binaries and emit manual-removal guidance
4. **Step 3** — Remove global npm links/installs for `@hiero-ledger/solo` and `@hashgraph/solo`
5. **Step 4** — Run `npm install` with system CA certs injected for corporate proxy compatibility, then warm Docker image cache via `solo cache image pull`

`post_install` provides a final guard: if a non-Homebrew binary is still present at `$HOMEBREW_PREFIX/bin/solo`, it emits a warning (`opoo`) with removal instructions. It does NOT call `odie` — that would mark the keg broken even though the install succeeded.

## Known Pitfalls

Do not reintroduce these patterns:

- **`Language::Node`** — removed from Homebrew in 2023. Use `std_npm_args` instead (see `hiero-cli.rb`).
- **Backtick subprocesses** — use `Utils.safe_popen_read` or `shell_output`. Backticks bypass Homebrew's subprocess sandbox.
- **`odie` in `post_install`** — `odie` signals a fatal install failure and marks the keg broken. Use `opoo` + `return` for warnings that don't block the install.
- **`s/Solo/SoloAT.../g` in the update script** — this corrupts user-facing strings inside `ohai`/`opoo` calls. Only the class declaration line needs changing: `s/^class Solo </class SoloAT${SUFFIX} </`.
- **Missing `license` field** — `brew audit` requires it. All new formulas need `license "Apache-2.0"`.
- **Missing `bottle :unneeded`** — add to npm-based formulas to signal no compiled artifact.
- **Hand-editing versioned `solo@*.rb` files** — these are frozen historical snapshots; only the update script should produce them.

## Update Script Invariants

If `update-solo-formula.sh` fails mid-run, it will attempt to remove any partially-written versioned formula. If it cannot clean up automatically, reset with:

```bash
git restore Formula/
```

The trap fires on any `ERR` (due to `set -euo pipefail`). Do not remove the trap or the `_VERSIONED_FORMULA_CREATED` sentinel.
